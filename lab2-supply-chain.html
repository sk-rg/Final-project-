What it is

A supply chain attack hits the code you depend on instead of your own code. Wanderly’s booking page is clean, but it loads a booking library from a public CDN, and that library gets modified to copy what visitors type. OWASP files this under A08 Software and Data Integrity Failures, with CWE-829.

The line

@latest lets whoever controls the CDN decide which code runs on your page, and with no integrity attribute the browser never checks it.

Try it

3 easy steps: (1) Press a booking, or fill the form and press Submit: the page runs a modified library from the CDN, and everything you typed, card number included, appears in the attacker panel. (2) Switch to Fixed: the attacker panel is cleared. (3) Submit again: the browser refuses the modified library and nothing leaks.

    Why it matters

    Customer details are exposed, privacy is violated, and leaked data can be used for phishing. In 2024 the polyfill.io domain was sold, and the new owner began serving malicious JavaScript to more than 100,000 websites that still embedded it. Those sites had changed nothing themselves.

    Version of the code

    In this lab the hash check runs in JavaScript so you can watch it. On a real site you only add the integrity attribute and the browser does the check for you.
