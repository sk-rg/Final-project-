What it is

ReDoS abuses a regular expression that can match the same text in many different ways. When a match fails, the engine tries every way before giving up, so one short input can keep the CPU busy for seconds or minutes. It is an availability bug in input validation, tracked as CWE-1333.

The line

([A-Z0-9]+)+ puts a repeat inside a repeat. With A’s followed by !, the ways to split the A’s roughly double with every extra character, and the match still fails.

Try it

3 easy steps: (1) Press “Valid licence”: it is answered at once. (2) Press a Payload (try the big one): the server freezes and other citizens’ lookups wait. The lab stops it by itself after 20 seconds. (3) Switch to Fixed and press the same Payload: it is answered at once.

    Why it matters

    One request can stall a shared service, and everyone else waits. In 2016 a regex that trimmed whitespace took Stack Overflow offline for about 34 minutes. In 2019 a single regex in a Cloudflare firewall rule used so much CPU that a large part of its traffic failed.

    The fix

    Version of the code

    The regex is not the only layer: cap the input length, avoid nested repeats, and use a linear-time engine such as RE2 or a timeout for untrusted patterns.
