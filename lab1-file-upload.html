Case 101: Profile Dashboard

What it is

Unrestricted file upload happens when a site accepts a file without checking what it really is. This profile page decides that a file is a photo by looking only at its name, so a script renamed photo.jpg is accepted. OWASP lists this under A04 Insecure Design, and it maps to CWE-434.

The line

The check reads file.name, which the visitor controls. A name is a label, not a fact about what is inside the file.

Try it

3 easy steps: (1) Press “Normal photo”: a real image is accepted. (2) Press a payload: a script disguised as a photo is accepted, then the server runs it. (3) Switch to Fixed and press the same payload: it is rejected. You can also choose your own file.

    Why it matters

    A script that runs on the server gives the attacker a shell with the web server’s permissions, enough to read data or hide a backdoor. In 2020 attackers abused an upload flaw in the File Manager plugin for WordPress (CVE-2020-25213) on hundreds of thousands of sites.

    The fix

    Version of the code

    Nothing is uploaded here: the check runs in your browser on the real bytes of the file, and the “shell” is only text in the log. A real site also renames the file, stores uploads outside the web root, and never lets that folder run code.
